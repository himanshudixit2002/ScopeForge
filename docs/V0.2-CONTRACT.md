# ScopeForge 0.2 implementation contract

Backward-compatible additions; existing fields/routes remain. Source version0.2.0. No live third-party testing during implementation. Preserve one GET per real scan, exact origins/default ports, public address pinning, no redirects, expiry/revoke/write-boundary pacing. Existing single local worker remains.

## Scan and program extensions
- Program adds `allowed_profiles: string[]` from `headers|web`. Existing real programs default `["headers"]`; demo supports both. ProgramCreate optional default `["headers"]`. At least one unique profile. Profiles describe what permission permits; changing existing program not required v0.2, create new permission record if expanding.
- ScanCreate adds `profile: "headers"|"web"` default headers. Demo UI chooses web. Profile web reads <=128KiB uncompressed HTML body in memory under existing overall response cap/deadline, executes no scripts, follows no links, stores no raw body. Scan returns `profile`, `source` (scan|http-import|openapi|manual), `summary` object describing observed analysis context when available. Legacy fields retained. Mode enum extends demo|passive|import|manual for stored results; create scan accepts only demo|passive.
- POST /scans/batch body `{program_id,target_urls:string[],profile}` →202 `{scans:Scan[],submitted:number,request_budget:number}`. 1..20 distinct explicit URLs; all-or-nothing validate and insert under queue100 capacity transaction. Real program only; each URL oneGET. Respect allowed profiles and exclusions. No discovery.
- POST /scans/cancel-all body `{program_id?:string}` → `{cancelled:number}`. Existing per-scan cancel retained.
- GET /checks → CheckDefinition[] `{id,title,category,profiles:string[],severity,cwe:string|null,description,limitations,reference_url}`. Catalog includes actual implemented scanner rules and root offline OpenAPI rules.

## Findings and history
Finding adds `source`, `cwe:string|null`, `first_seen`, `last_seen`, `occurrence_count:number`. Preserve status/notes on rescan. Append immutable sanitized occurrence snapshot on each persisted observation (including first legacy occurrence via migration).
- GET /findings/{id}/occurrences → `{id,scan_id,observed_at,severity,evidence,source}[]` latest100.
- POST /findings body `{program_id,target_url,title,severity,confidence,description,impact,remediation,evidence,cwe?:string,notes?:string}` →201 Finding. Explicitly analyst-entered manual record, associated completed zero-network manual scan. Backend validates scope/authorization, reasonable lengths, CWE-123 syntax. Manual evidence is operator provided, tell users to redact; never auto-submit report. Demo program manual records stay synthetic.
- GET /programs/{id}/report?format=markdown|json → downloadable local program findings export with provenance/status/limitations. No report submission.
- Existing individual report includes source, first/last seen, recurrence, CWE, notes; mode-specific reproduction so imported API reviews don't say a GET was sent.

## Offline import
- POST /imports/analyze body `{program_id,target_url,format:"http"|"openapi",content:string}` →201 `{scan:Scan,findings_count:number,warnings:string[]}`. Max content256KiB UTF-8; request wrapper /api/imports/analyze cap1MiB (other routes32KiB). No multipart/filesystem path, no outbound requests/DNS. Validate target URL+scope+expiry, demo allowed labelled synthetic. Reject unsupported/malformed/oversized inputs; no raw content stored. Parsing errors422, consistent JSON. Run bounded parser within threadpool or sync route, depth/node limits.
- HTTP content is JSON object `{status:200,headers:[{name:"Content-Type",value:"text/html"},...],body:"optional HTML string"}`; reject unknown top-level fields, raw auth-header names/cookie values never persisted. scanner Snapshot used for analysis with body enabled; source-prefixed rule IDs `import-http:<id>` prevent conflating network findings. imported snapshot clearly says user-provided capture, not network observation. No secrets echoed on errors.
- OpenAPI content JSON3.0/3.1/3.2 only, no YAML/XML/remote refs. Root `offline.py` implements `analyze_import(format, content, target, synthetic=False)` → `(observations:list[dict],checks:list[str],warnings:list[str],summary:dict)`. Findings target base URL; route template evidence sanitized/bounded; no described endpoint contacted or automatically added to scope. Root supplies `OPENAPI_CHECKS` metadata; scanner catalog supplies `get_checks()` list or CHECK_DEFINITIONS. Need only local refs bounded; reject malicious shape/depth and unsupported versions.
- Root will provide `backend/scopeforge/offline.py`; backend agent imports function lazily if needed. Root preserves scanner Snapshot backward compatibility with added default body/metadata fields coordinated scanner agent.

## Frontend additions
